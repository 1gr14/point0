Переопределяемый сокет-транспорт — как fetchFn, и тест-утилиты для сокетов
(`socketFn` на поинтах / `engine.withSocket` либо внутрь
`engine.withFetch`-механики; гонять сокетную часть с сервера и из тестов без
браузера). ОБСУЖДАЕТСЯ С СЕРГЕЕМ перед реализацией — дизайн сначала.

ОЦЕНКА 2026-07-24: в архитектуру встаёт бесшовно ПОТОМ, сейчас не делать — шов
узкий и готовый (ровно две точки дозвона в core: голый сокет и upgrade-connect;
вся машинерия выше работает с утиным `WebSocketLike`), протокол кадров
транспорт-агностен, опция чисто аддитивна (wire/типы не трогаются). Ничего не
блокирует: у Bun есть родной WebSocket — int-тесты уже гоняют настоящий
клиент-рантайм без браузера. Настоящий дизайн-вопрос — не транспорт, а модель
«сокет-клиент на сервере»: side-гарды намеренно кидают на сервере, менеджер
живёт в клиентском рантайме; серверному клиенту нужен свой менеджер вне React
(холды, `_point0_env.side`) — это и обсуждать.

Заготовленное место для СЕРВЕРНОЙ стороны (решение 2026-07-24): опция движка
называется `socket: boolean` именно с прицелом сюда — по аналогии с `backplane`
она расширится из булеана (`socket: boolean | опции/транспорт`) и станет точкой
передачи серверного транспорта. Клиентская сторона — `socketFn` на поинтах /
`engine.withSocket`.

Клиентская половина исходной задачи («сокет-клиент в тестах без сервера»)
СДЕЛАНА и отгружается с фичей — через **FakeClient**, не через withFetch (внутри
`engine.withFetch` сторона остаётся серверной, и это правильные гарды):
сокет-глобалы живут в суперсторе, in-memory сокет-пара — `openInMemorySocket` с
топик-брокером в EngineSocket; см. [dev/docs/socket.md](../docs/socket.md),
раздел «In-memory sockets (FakeClient)». Эта карточка остаётся про ВНЕШНИЙ
переопределяемый транспорт (socketFn для нестандартных сетей) и серверную опцию
`socket: boolean | транспорт` — отдельная, более поздняя история.
